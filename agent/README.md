# О!дин запрос — ИИ-агент для путешествий

Прототип для хакатона Островка, трек «О!дин запрос». Пользователь пишет **одно сообщение своими словами** («хочу к тёплому морю в ноябре, недорого, с ребёнком, без долгих перелётов»), а агент ведёт его по всему пути: понимает запрос, предлагает направления, подбирает отели, дорогу и трансферы, проверяет стыковки, собирает корзину и имитирует оплату. Когда условия меняются («на два дня позже», «бюджет меньше», «с нами собака»), план **пересобирается частично**, а не ищется с нуля.

> **Данные синтетические.** У проекта нет доступа к API и данным Островка. Все направления, отели, рейсы, цены, погода и правила въезда вымышлены (см. [Моковые данные](#моковые-данные-и-демо-режим)). Оплата — имитация, деньги не списываются.

**Фокус — поездки по России** (из Москвы, Санкт-Петербурга, Казани, Екатеринбурга, Новосибирска): организаторы трека просили выбрать одну локацию и не распыляться. Архитектура и интерфейсы от страны не зависят: зарубежные направления, визы и международные рейсы поддерживаются кодом (`visa_required`, `entry_note`, `international`), просто в моковых данных их сейчас нет.

Репозиторий — **основа**, на которой команда строит фичи: слои разделены, источники данных и LLM подключаются через интерфейсы, поведение агента покрыто тестами.

## Быстрый старт

Нужны [uv](https://docs.astral.sh/uv/) и Python 3.12 (uv поставит его сам).

```bash
uv sync                 # зависимости из uv.lock
uv run odin             # сервер на http://127.0.0.1:8000
```

Откройте http://127.0.0.1:8000 — это веб-чат. Документация API — на `/docs`.

**Без ключа LLM** запускается **демо-режим**: вместо модели работает детерминированная заглушка, которая понимает типовые формулировки и проходит весь путь на тех же инструментах. Режим виден в шапке чата и в `GET /api/health`. Попробуйте по очереди:

1. «Хочу к тёплому морю в сентябре, недорого, с ребёнком, без долгих перелётов» (в России это Анапа и Сочи; в ноябре вода уже холодная, и агент честно скажет, что подходящего нет)
2. «Давай первый вариант»
3. «А можно на два дня позже?»  (затем «С нами будет собака», «Бюджет меньше»)
4. «Оформляй» → «Оплачиваю»

**С настоящей моделью** по умолчанию используется DeepSeek Flash — OpenAI-совместимая модель с tool calling. Получите ключ на [платформе DeepSeek](https://platform.deepseek.com/api_keys), задайте `LLM_API_KEY` в `.env` и запускайте агента:

```bash
cp .env.example .env    # и заполните LLM_API_KEY, LLM_BASE_URL, LLM_MODEL
uv run odin
```

| Провайдер | `LLM_BASE_URL` | Заметки |
|---|---|---|
| DeepSeek (по умолчанию) | `https://api.deepseek.com` | `LLM_MODEL=deepseek-flash` |
| OpenAI | `https://api.openai.com/v1` | `LLM_MODEL=gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | модель вида `провайдер/модель` |
| Ollama / vLLM | `http://localhost:11434/v1` | ключ — любая непустая строка; нужна модель с tool calling |
| Российские модели | адрес API провайдера | подойдёт любая, у которой есть OpenAI-совместимый API с вызовом функций (tool calling): достаточно указать её `LLM_BASE_URL`, `LLM_MODEL` и ключ; без такого API нужен отдельный адаптер за протоколом `LLMClient` |

Ошибки провайдера (неверный ключ, адрес, модель без tool calling, лимиты) приходят в чат с подсказкой, что поправить в `.env`.

## Что умеет агент

- **Понимает явное и скрытое.** Бюджет, даты, состав группы — и то, что стоит за словами: с ребёнком → бассейн, детский клуб, дневные рейсы, детское кресло; с питомцем → только отели и перевозчики, которые их принимают. Догадки записываются как *допущения* и озвучиваются пользователю; уточняется только необходимое, без анкеты. Жёсткие пожелания («без пересадок», «с бесплатной отменой», звёзды, питание, предел времени в пути, бюджет) — поля запроса, которые подбор действительно соблюдает, и их можно снять («неважно, сколько лететь»); свободные заметки (`notes`) подбор не читает, и модели велено проверять такие пожелания по результатам самой.
- **Предлагает направления с объяснением:** цена «от», погода месяца, время в пути, плюсы и минусы, а для отброшенных — причина («Байкал — дорога от 5,9 ч, а вы просили не дольше 5 ч»).
- **Сравнивает не только по цене:** условия отмены, питание, расположение, время «от двери до двери», пересадки, время суток, багаж, возвратность, детское кресло. Каждый выбор объясняется: *почему подходит · чем пожертвовали · риски*.
- **Проверяет стыковки** в часовом поясе направления: прилёт ↔ трансфер ↔ заселение, выселение ↔ трансфер ↔ вылет, ночные приезды, короткие пересадки, питомцы, вместимость номера, бюджет. Ночной поезд или дальний перелёт отправляются накануне заезда, чтобы прибыть вовремя.
- **Пересобирает, а не ищет заново:** изменение условий затрагивает только часть плана, прежний выбор сохраняется, если он ещё подходит, выбор пользователя закрепляется, бюджет добирается заменами с минимальной потерей качества; в ответе — что осталось, что обновилось, что заменено.
- **Оформляет:** корзина из полного плана без ошибок, имитация оплаты, коды подтверждения.

## Стек и обоснование

| Слой | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12 | экосистема LLM, скорость прототипирования; `StrEnum`, обобщения PEP 695 |
| Веб | FastAPI + uvicorn | async (провайдеры и LLM — сетевой ввод-вывод), OpenAPI «из коробки», нативная связка с Pydantic |
| Модели | Pydantic v2 | одни модели для домена, валидации аргументов инструментов, JSON Schema для tool calling и ответов API |
| LLM | `openai` SDK за протоколом `LLMClient` | провайдер меняется через `.env`; цикл агента зависит от протокола и собственных типов сообщений, а не от SDK |
| Настройки | pydantic-settings, `.env` | ключ, адрес и модель — из окружения |
| Зависимости | uv (`uv.lock`) | быстрые воспроизводимые окружения |
| Интерфейс | HTML + CSS + ES-модули | «без тяжёлой сборки»: ни npm, ни бандлера; FastAPI раздаёт статику |
| Качество | pytest + pytest-asyncio, ruff, mypy | тесты, линтер и форматтер, проверка типов (`uv run mypy`) |

Сознательно не взяты LangChain/LlamaIndex (прячут цикл агента и усложняют детерминированные тесты) и Streamlit/Gradio (быстро, но неудобно для API и будущего бота).

## Архитектура

```
 web (HTML/JS) ──HTTP──▶ api ──▶ agent ──▶ llm: OpenAI-совместимый клиент │ демо-заглушка
                                   │
                                   ▼
                               services ── TripSearch · TripPlanner · CheckoutService
                                   │
                  ┌────────────────┴────────────────┐
                  ▼                                 ▼
              providers                          domain
   Protocol-интерфейсы + моки              модели и чистые правила
   (каталог, погода, отели, рейсы,         (стыковки, сравнение, пересборка):
    трансферы, оплата, бронь)              без ввода-вывода, LLM и веб-фреймворка
```

Зависимости направлены внутрь: `domain` ← `providers`, `services` ← `agent` ← `api`. Домен ничего не знает о сети, LLM и FastAPI, поэтому вся важная логика тестируется быстро и детерминированно.

**Главный принцип: модель понимает и формулирует, код считает и проверяет.** LLM превращает слова в структурированный запрос (`update_trip_request`), вызывает инструменты и пишет ответ. Фильтры, ранжирование, стыковки, пересборка и бюджет — обычный код: его результат можно проверить тестом, а объяснения «почему / чем пожертвовали / риски» строятся из тех же фактов, что и выбор, поэтому модели не из чего выдумывать.

**Один ход диалога** (`agent/loop.py`):

1. В историю добавляется сообщение пользователя; к системному промпту дописывается актуальное состояние (запрос, план, какие части устарели, корзина, заказ).
2. Модель отвечает текстом или просит инструменты; они выполняются по очереди, результаты возвращаются модели. Ошибки (неверные аргументы, доменные, непредвиденные) возвращаются *как результат*, чтобы модель исправилась, а не роняли диалог.
3. Цикл ограничен `AGENT_MAX_STEPS`; при исчерпании модель просят подвести итог (`tool_choice="none"`, описания инструментов остаются: шлюзы к некоторым моделям отвергают историю с вызовами без них). Если модель недоступна до первого действия, ход откатывается целиком и можно повторить то же сообщение; если действия уже выполнены (изменён запрос, собран план, оплачен заказ), история сохраняется, а вместо ответа пользователь получает пояснение, потому что состояние и разговор не должны расходиться.

**План и пересборка** (`domain/plan.py`, `domain/rebuild.py`, `services/planner.py`). План — пять частей (*слотов*): дорога туда, отель, дорога обратно, трансфер в отель, трансфер из отеля. Трансфер зависит от рейса и отеля. При изменении запроса `stale_slots` определяет, какие части устарели (даты → дорога и отель, питомец → всё, «звёздность» → отель), `choose` оставляет прежний вариант, если он почти так же хорош, `fit_to_budget` добирает бюджет заменами с минимальной потерей качества, `diff_plans` сообщает, что изменилось. Если после частичной пересборки итог не укладывается в бюджет, пересматриваются и нетронутые, не закреплённые пользователем части. Ревизия плана растёт монотонно в рамках сессии (в том числе при смене направления) и остаётся прежней, только если предложения и проблемы те же.

**Защиты в коде, а не только в промпте** (`agent/tools`, `services/checkout.py`): оплата возможна только для корзины, которую пользователь уже видел в предыдущем ходу, актуальной ревизии плана, при актуальном запросе (план не отстаёт от него), без блокирующих проблем и с `confirmed=true`; после покупки изменения закрыты; корзина от прежней ревизии плана сбрасывается; в корзину попадает только полный план без блокирующих проблем. Оплата идемпотентна: ключ — id корзины, номер заказа выводится из него, поэтому повтор после сбоя бронирования не списывает деньги дважды.

    llm/                 LLMClient, OpenAI-совместимый клиент, демо-заглушка (stub/)

## Как расширять

**Подключить реальный источник данных.** Реализуйте нужный `Protocol` из `providers/interfaces.py` (все методы асинхронные) и передайте реализацию в контейнер `Providers` — `create_app(providers=...)` или `build_mock_providers()` как образец. Например, `WeatherProvider` можно заменить на запрос к Open-Meteo, а `HotelProvider`/`TransportProvider` — на поиск по API партнёра. Требования к предложениям: цена — за всю группу (`total_price_rub`), `id` стабилен между датами (по нему план узнаёт тот же рейс или тариф при пересборке), время — aware-datetime в поясе пункта.

**Добавить инструмент агента.** В модуле `agent/tools/` опишите аргументы (наследник `ToolArgs`, поля с `Field(description=...)` — это то, что читает модель), обработчик `async def handler(ctx: ToolContext, args) -> dict` и `Tool(...)`, добавьте в `TOOLS` модуля и в `default_tools()`. Ожидаемые ошибки — `ToolError` или `DomainError` (текст уйдёт модели), в результат стоит класть короткий `summary` (он виден в «Что делал агент»). Схема параметров упрощается автоматически (`tools/schema.py`).

**Изменить сравнение.** Новый критерий — функция `option -> Verdict(score, pro, con, risk)` и строка в списке `Criterion(...)` в `domain/scoring/*.py`. Жёсткие условия — `reject_when(причина, предикат)` в соответствующем `screen_*`. Веса стиля бюджета («недорого» / «лишь бы удобно») — `scoring/common.py`.

**Добавить проверку стыковок.** Функция `plan -> list[Issue]` в `domain/junctions.py`, код — в `IssueCode`, добавьте её в кортеж `checks`.

**Добавить направления и отели.** Правьте `providers/mock/data/*.json` (`places`, `destinations`, `climate`, `hotels`, `trains`): модели валидируют данные при загрузке, а тест проверяет, что у каждого направления есть погода на все месяцы, отели и рейсы из Москвы.

## API

| Метод и путь | Назначение |
|---|---|
| `POST /api/sessions` | начать диалог, вернуть состояние |
| `GET /api/sessions/{id}` | состояние: запрос и его сводка, план, устаревшие части, корзина, заказ, стенограмма |
| `POST /api/sessions/{id}/messages` | сообщение `{"text": "..."}` → `{reply, steps, state}` |
| `GET /api/health` | состояние сервиса и режим LLM |

```bash
SID=$(curl -s -X POST localhost:8000/api/sessions | python3 -c 'import sys,json; print(json.load(sys.stdin)["session_id"])')
curl -s -X POST localhost:8000/api/sessions/$SID/messages \
  -H 'Content-Type: application/json' \
  -d '{"text": "Хочу к тёплому морю в сентябре, недорого, с ребёнком, без долгих перелётов"}'
```

Ошибка LLM до первого действия агента (неверный ключ, адрес, лимиты, странный ответ провайдера) → `502` с подсказкой; неизвестная сессия → `404`; пустое или слишком длинное сообщение → `422`. Сбой модели после выполненных действий не ошибка: ответом приходит пояснение, а состояние сохранено.

## Моковые данные и демо-режим

- **10 направлений по России** (Сочи, Анапа, Калининград, Казань, Санкт-Петербург, Кисловодск, Карелия, Алтай, Байкал, Красная Поляна), 38 отелей с тарифами (питание, условия отмены, расстояния, занятые даты), климат по месяцам, сезонные цены. Правила въезда для внутренних поездок не нужны и в данных пустые. Реальное расписание не воспроизводится: например, аэропорт Анапы в жизни закрыт, а в моке рейсы туда есть.
- **Рейсы генерируются** детерминированно по расстоянию между городами: расписание и номера рейсов зависят от маршрута, цена — ещё и от даты; дальние маршруты (Байкал, Алтай, Калининград из Сибири) получают варианты с пересадкой через крупный город по пути; времена — в поясах аэропортов. Поезда — по таблице маршрутов (Москва — Санкт-Петербург, Казань, Сочи, Карелия; Санкт-Петербург — Карелия; Сочи — Красная Поляна), в том числе ночные.
- **Перевозчики и отели вымышлены**; совпадения с настоящими случайны.
- **Демо-заглушка — не модель.** Это набор правил разбора текста; она нужна, чтобы весь путь можно было пройти и проверить без ключа. Для произвольных формулировок подключите LLM.
- Клиент OpenAI-совместимого API проверен тестами на подделке SDK (формат запроса, разбор ответа, все виды ошибок); на живом провайдере в рамках подготовки основы он не запускался — первый запуск с ключом стоит сопроводить просмотром «Что делал агент».

Тесты не ходят в сеть. Дата «сегодня» в тестах фиксирована (`tests/conftest.py`), агент получает её через `clock`.

## Ограничения и что логично делать дальше

- Сессии хранятся в памяти процесса без вытеснения и авторизации; один процесс.
- Цены не перепроверяются у «поставщика» перед оплатой (нужен re-quote при создании корзины), а при сбое бронирования после списания нет возврата: оплата идемпотентна, но компенсация (`refund`) не реализована.
- История диалога не сжимается (около 6–7 КБ на ход), а общего таймаута хода нет: каждый запрос к модели ограничен `LLM_TIMEOUT_SECONDS`, SDK повторяет его при сетевых сбоях. Для моделей с маленьким контекстом и долгих диалогов нужны сжатие старых результатов инструментов и дедлайн хода.
- Окно поездки — дни проживания в отеле. Дорога туда ищется на день заезда и накануне (ночной поезд, дальний перелёт) и должна прибыть в сутки заезда: с 06:00 его дня до 06:00 следующего. Лишняя ночь до или после дороги, ранний и поздний заезд как отдельные услуги не планируются.
- Один маршрут «город → направление → город»: мультигород и открытые даты (поиск самой дешёвой даты в месяце) — следующий шаг.
- Нет стриминга ответа и фоновых уведомлений; нет набора эталонных диалогов для оценки качества на живой модели.
